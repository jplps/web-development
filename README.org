* Web Development
  A hands-on course on web application development, from fundamentals to full-stack.

** Concept
   This repository supports learning progression from introductory to advanced levels in web development. Follow the lessons in numerical order, or jump to any topic you need.

   1. Comments in the code describe the program's flow and the reasoning behind each step.
   2. Uncommented code serves as a reading exercise for the language in question.
   3. Default web root on Debian-based distributions: =/var/www/html=
   4. Access your application in the browser at =http://localhost/path/to/file=

** Context
*** Web Applications
    A web application is a program that runs over the internet. It communicates with the user's browser via HTTP, processing requests and returning responses. The user initiates actions through the browser, and the application responds with content generated on the server, on the client, or both.

*** Static vs. Dynamic Content
    A *static* page is one whose content does not change in response to user interaction. It is written once and served as-is (e.g. a plain HTML document). Manual editing by the developer does not count as dynamism.

    A *dynamic* page changes its content based on user input, database queries, or other runtime conditions. This can happen server-side (PHP generating HTML) or client-side (JavaScript manipulating the DOM).

*** Markup Languages
    Markup languages use tags to structure and describe content for the browser to render. HTML is the foundational markup language of the web. The browser *renders* HTML and CSS but does not execute them the way it executes JavaScript.

    XML (Extensible Markup Language) is a related standard used for structured data exchange (e.g. APIs, configuration files). Unlike HTML, XML does not have predefined tags.

** HTML5
   HTML (HyperText Markup Language) structures web content using elements called *tags*. "HyperText" refers to text containing hyperlinks -- references that connect documents to one another.

   HTML handles text, images, audio, and video. It is standardized by the W3C. Any file with the =.html= extension will be interpreted as an HTML document by the browser.

*** Rules
    - Complete tags must be closed: =<p>= ... =</p>=
    - Void tags are self-closing and must not have a closing tag: =<img>=, =<br>=, =<input>=
    - Tag and attribute names should be lowercase
    - Nested tags are closed in reverse order (last opened, first closed)
    - Use indentation to make the nesting structure visible

    Basic HTML skeleton:
    #+begin_example
    <!DOCTYPE html>
    <html>
      <head>
        <title>Document Title</title>
      </head>
      <body>
        <h1>Main Heading</h1>
        <p>A simple page.</p>
      </body>
    </html>
    #+end_example

** CSS3
   CSS (Cascading Style Sheets) controls the visual presentation of HTML documents: fonts, colors, spacing, layout, positioning, and layering of elements.

   CSS is not a programming language and not a markup language. It is a *style sheet language* with its own rule-based syntax. Separating style from structure keeps HTML files focused on content and makes designs easier to maintain.

*** Selectors
    A selector targets one or more HTML elements and applies a set of style declarations to them.

    #+begin_example
    p {
      color: #aabbcc;
      background-color: #ff0;
      font-style: italic;
      text-align: right;
      width: 300px;
      font-size: 1.5em;
    }
    #+end_example

    Multiple selectors can share the same declarations:

    #+begin_example
    h1, p, ul {
      color: #aabbcc;
      font-style: italic;
      text-align: right;
    }
    #+end_example

    Elements are targeted by tag name, class, or id:

    | HTML                           | CSS Selector   |
    |--------------------------------+----------------|
    | =<p class="center">=           | =p.center=     |
    | =<p id="id001">=               | =#id001=       |

    Rules: IDs must be unique per page. Class and ID names should not start with a digit or contain spaces or special characters.

*** Colors
    - *RGB*: =rgb(22, 117, 49)= -- each channel ranges from 0 to 255 (256^3 = ~16.7 million combinations).
    - *Hexadecimal*: =#1CA71A= -- shorthand for RGB values in base 16.
    - *RGBA*: =rgba(12, 200, 99, 0.6)= -- adds an alpha channel (0 = transparent, 1 = opaque).

** JavaScript (ECMAScript)
   JavaScript is the programming language of the browser. It enables dynamic, interactive behavior on the client side: responding to events, manipulating the DOM, validating forms, and communicating with servers asynchronously.

   Despite the name, JavaScript is unrelated to Java. It follows the ECMAScript specification (hence the =01-ecma= directory name).

   Topics covered in this repository:
   - Variables, data types, and type conversions
   - DOM manipulation (=innerHTML=, element selection)
   - Events and =this= context
   - Functions (declarations and literal/anonymous functions)
   - Pop-ups (=alert=, =confirm=, =prompt=)
   - Regular expressions
   - Client-server interaction

** AJAX
   AJAX (Asynchronous JavaScript and XML) allows a web page to exchange data with a server *without reloading the entire page*. This enables smoother, more responsive user interfaces.

   Despite the name, AJAX commonly uses JSON rather than XML in modern practice. The core mechanism is the =XMLHttpRequest= object (or the newer =fetch= API).

   Topics covered:
   - Dynamic page updates without reload
   - GET and POST requests
   - Server-side SQL operations via AJAX
   - Form submission and processing

** PHP
   PHP (originally "Personal Home Page," now "PHP: Hypertext Preprocessor") is a server-side scripting language. Code written in PHP is executed on the server, and the resulting HTML is sent to the browser.

   PHP was created by Rasmus Lerdorf in 1994. Combined with Apache (web server) and MySQL (database), it forms a classic development stack (LAMP on Linux, or equivalent).

   Topics covered:
   - Syntax fundamentals and data types
   - Operators and control structures
   - Arrays (indexed, associative, multidimensional)
   - Functions and includes
   - Form handling (GET/POST)
   - Object-oriented programming
   - Database interaction (MySQL)

** Client-Side vs. Server-Side
   - *Client-side* code (HTML, CSS, JavaScript) runs in the user's browser. The browser downloads the files and processes them locally.
   - *Server-side* code (PHP, Python, etc.) runs on the web server. The server processes the code and sends the result (usually HTML) to the browser.

   This distinction is independent of whether a language is interpreted or compiled. PHP is interpreted on the server; JavaScript is interpreted in the browser. Both are interpreted, but they run in different environments.
